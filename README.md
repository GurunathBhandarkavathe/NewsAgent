# Samachar Bharat NewsAgent

Samachar Bharat NewsAgent is a local-first Python app that drafts Instagram posts from India-focused trending news. It gathers stories, scores and deduplicates them, creates 1080x1350 slides, writes detailed Instagram descriptions with context and source links, and waits for human approval before posting.

## What It Builds

- One 4-5 story draft every 3 hours in IST.
- Default publishing mode is one separate Instagram feed post per story, so each story gets its own detailed caption.
- Categories: politics, films, sports, current affairs, and international.
- Sources: direct publisher RSS feeds, Google Trends India RSS, and GDELT DOC API.
- Default production image policy uses real article images and requires every selected story to have a loadable image; if enough real images are not available, the cycle is skipped instead of posting fallback cards.
- Local JSON session store with draft status, dedupe memory, and source logs.
- Approval dashboard with approve, reject, hold, regenerate description, and regenerate images.
- Meta Instagram Graph API publishing when credentials and public image hosting are configured.
- Manual export fallback when Meta credentials or public asset URLs are missing.
- Samachar Bharat branding on dashboard, descriptions, and generated slides.
- Slide text uses clear news-brief sentences instead of headline-only text.
- Instagram descriptions include detailed context, courtesy, and a full-report link for each post.
- Selected real stories are enriched from article-page metadata/body text before captions are written, so descriptions are fuller than short RSS snippets when the source page allows extraction.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install ".[dev]"
cp .env.example .env
```

Run a mocked draft first:

```bash
newsagent run-once --mock
newsagent serve
```

Open `http://127.0.0.1:8000`.

Run one real collection cycle:

```bash
newsagent run-once
```

Run continuously with the dashboard:

```bash
newsagent run --immediate
```

By default, the worker aligns future cycles to 3-hour IST boundaries.

## Meta Setup

Open `http://127.0.0.1:8000/setup/meta` after you have a Professional Instagram account linked to a Facebook Page and Meta developer app.

Paste:

- `INSTAGRAM_BUSINESS_ACCOUNT_ID`
- `META_ACCESS_TOKEN`
- `PUBLIC_ASSET_BASE_URL`
- `PUBLIC_ASSET_TOKEN`, generated by the setup page

If your HTTPS tunnel or domain points to this dashboard, set:

```text
PUBLIC_ASSET_BASE_URL=https://YOUR-HTTPS-HOST/public-assets/PUBLIC_ASSET_TOKEN/
```

Use the setup page's **Test Connection** button, or run:

```bash
newsagent test-meta
```

The test checks the Meta account lookup and builds a sample public slide URL without publishing anything.

## Production Run

Check production readiness:

```bash
newsagent doctor
```

Run the Samachar Bharat production pipeline continuously:

```bash
newsagent production
```

The production command starts the approval dashboard and creates a real draft immediately, then continues every 3 hours on IST boundaries. It does not publish without dashboard approval.

## Local-Only Use

This project is intended for one-owner use. Keep `DASHBOARD_HOST=127.0.0.1`
for normal local operation, and set `DASHBOARD_TOKEN` before exposing the
dashboard through any HTTPS tunnel. Drafts, seen-story dedupe memory, and logs
are stored in `NEWSAGENT_SESSION_PATH`, which defaults to
`data/session-store.json`.

## GitHub Actions Posting

The repository includes `.github/workflows/publish-instagram.yml` for an
optional owner-only hosted run. It creates one draft, uploads the generated
slides to GitHub Pages so Meta can fetch public HTTPS images, then publishes
that exact draft id through Meta as separate feed posts by default.

Add these repository secrets before enabling the workflow:

- `INSTAGRAM_BUSINESS_ACCOUNT_ID`
- `META_ACCESS_TOKEN`
- `META_API_HOST`, optional; leave blank for auto-detection

Enable GitHub Pages for Actions in the repository settings. The workflow can be
run manually from the Actions tab and is also scheduled every 3 hours on IST
boundaries.

Example always-on launch files are included:

- macOS LaunchAgent: `deploy/macos/com.samachar-bharat.newsagent.plist.example`
- Linux systemd: `deploy/systemd/samachar-bharat-newsagent.service.example`
- Docker Compose: `deploy/docker/docker-compose.yml`
- Direct script: `scripts/run-samachar-bharat-production.sh`

## Instagram Publishing

Approved drafts publish through Meta's Instagram Content Publishing flow when these values are set in `.env`:

- `INSTAGRAM_BUSINESS_ACCOUNT_ID`
- `META_ACCESS_TOKEN`
- `PUBLIC_ASSET_BASE_URL`
- `META_GRAPH_VERSION`, default `v26.0`

`PUBLIC_ASSET_BASE_URL` must be an HTTPS URL that publicly serves the local `assets/` directory. If any publishing requirement is missing, approval exports a manual package instead of failing.

The default `POST_FORMAT=separate_posts` publishes each selected story as its
own feed post with a story-specific caption. Set `POST_FORMAT=carousel` only if
you want the older one-carousel-per-cycle behavior.

`ARTICLE_DETAIL_ENRICHMENT=true` fetches the selected article pages and extracts
additional article context for the `Full brief` section of each post caption.

Useful references:

- Meta Content Publishing: https://developers.facebook.com/documentation/instagram-platform/content-publishing
- Instagram Platform: https://developers.facebook.com/documentation/instagram-platform
- IG User Media: https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/media
- GDELT data/APIs: https://www.gdeltproject.org/data.html
- Google Trends India: https://trends.google.co.in/trending

## Image Rights

The default production setting is `IMAGE_POLICY=article_images` with
`REQUIRE_REAL_IMAGES=true`, so generated posts use real article images and skip
cycles when enough real images are not available. The image extractor filters
common logo/icon/placeholder URLs, but article images can still carry rights
risk. Manual review is recommended for local approval flows, and every post
keeps visible courtesy/source text.

Set `IMAGE_POLICY=branded_cards` only if you want the older no-external-image
fallback card style.
